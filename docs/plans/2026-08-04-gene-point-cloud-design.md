# Gene expression 点云设计（多基因、密度编码）

日期：2026-08-04　状态：设计已确认，待实施
前置：`2026-08-04-gene-atlas-layer-design.md`（数据管线）

## 摘要

把 Gene expression 图层从"每区一个标记"改为"点亮基因所在脑区的体素点云"。
多基因同屏各自一色，用**点亮密度**表达指标值，用**偏移 + 抖动**让同位置的
不同基因互不遮盖。

这不是给现有实现打补丁。现在的基因层**根本没在点云上表达基因**：
`drawAtlasPointGroups()` 按 `label.color` 着色、从不读 `geneValues`，点云只是
解剖底图；基因信号全在区域标记上。而且默认 `selectedCellType === ALL_CELL_TYPES`，
标记走 `drawCompositionGlyph()` 画细胞构成饼图——颜色与透明度完全不表达基因，
只有半径表达。本设计把信号搬到点云本身。

## 一、已确认的决策

| # | 决策 | 取舍 |
| --- | --- | --- |
| 1 | 全部选中的基因**同时画**，不设上限 | 性能实测支持（§六） |
| 2 | **密度 = 指标值，色相 = 基因身份** | 放弃最初设想的"颜色深浅表达值"：色相已被身份占用，一个通道不能承担两件事 |
| 3 | 点数随基因数**次线性**增长（`P/√n`）+ 抖动 | 单基因不稀疏，多基因不糊 |
| 4 | 着色单位是 **Allen 标签**而非 DigitalBrain 区域 | 海马 10 个亚区在 3D 上合并，差异改在详情面板逐条列出 |
| 5 | 置信度用**点大小** | 密度被值占用、色相被身份占用，大小是唯一空闲通道 |
| 6 | **屏幕网格命中** | 整片点云可点击，且能分辨点的是哪个基因 |
| 7 | 密度用**共用的语料级固定标定 + 分段非线性**；图例给标尺、丰度位标与数字 | 多基因的目的就是跨基因比较；固定标定使量程不随选中集合漂移；分段兼顾两端 |

## 二、通道分配

| 通道 | 编码 | 备注 |
| --- | --- | --- |
| 点亮**数量**（密度） | 指标值 | 共用的语料级分段标定 |
| **色相** | 基因身份 | 由宿主提供，与基因芯片同色 |
| 点**大小** | 解剖映射置信度 | 1.9 / 1.6 / 1.4 px |
| 偏移**方向** | 基因序号 | 纯渲染分离，无数据含义 |

density 是弱定量通道（Cleveland–McGill 的编码有效性排序里远弱于位置与长度），
所以**精确值一律由图例与 tooltip 的数字承担**，密度只负责格局。

## 四、点位与密度模型

### 4.1 分配律

对每个被声明的标签 L（体素点数 `P`）与 n 个选中基因：

```
窗口大小        k       = round(P / √n)
基因 i 的起点   start_i = round(i × P / n)              （环形回绕）
基因 i 的窗口           = order[start_i .. start_i + k)
点亮数          lit_i   = value_i > 0 ? max(3, round(k × norm_i)) : 0
点亮的点                = 窗口的前 lit_i 个
```

`order[]` 是该标签的一个**固定置换**，加载时以标签索引为种子算一次。
它存在的两个理由：

- **空间均匀**：窗口前段散布于整个标签体积，而不是聚在一角
- **值变化时不重排**：点亮数变化只是在窗口前段增减，已亮的点不跳位

### 4.2 密度标定：分段非线性

```
scale = index.densityScale[rule][metric]     // { breakpoint, reference, lowKnots[13] }
K     = 12      // 低段节点数
D_LOW = 0.70    // 低段分到的密度预算
P_HI  = 0.6     // 高段幂次

norm(v):
  v <= 0                → 0                                     // 不画
  v <= scale.breakpoint → 在 lowKnots 上分段线性插值，映射到 [0, D_LOW]：
                            取 i 使 lowKnots[i-1] < v <= lowKnots[i]
                            t = (v - lowKnots[i-1]) / (lowKnots[i] - lowKnots[i-1])
                            ((i - 1) + t) / K * D_LOW
  v >  scale.breakpoint → D_LOW + (1 - D_LOW)
                            * ((v - breakpoint) / (reference - breakpoint)) ** P_HI
```

`lowKnots` 有 K+1 = 13 项，第 i 项是语料在分位 `(i/K) × 0.90` 上的值，
`lowKnots[0] = 0`、`lowKnots[K] = breakpoint`；纵坐标是隐含的 `i/K × D_LOW`，不必存。
超出 `reference` 的值封顶为 1。低段是**语料 CDF 的分段线性逼近**，高段是次线性幂律。

这个形状不是挑的，是逐个候选测出来的。五段推理：

**（一）必须非线性。** `mean` 是 `log1p(CP10K)` 的组内均值，本身已在对数尺度上，
但**基因之间**的量程仍跨 351 倍（抽样 399 个基因：p10 = 0.0082，p99 = 2.88）。
更要害的是 pooled p50 = 0.0775，**只是参照 3.51 的 2.2%**——一半的数据挤在参照
量程最底部的百分之几里。共用线性量程下中位基因只能亮到 6.8%、p10 基因 0.3%
（全程贴着 3 点下限，不可分辨）。

**（二）单一幂律与 asinh 都不够。** 在语料上实测（密度 %）：

| 变换 | 值 p50 | 值 p90 | 值 p99 | 低丰度基因 max | 中位基因 max | 顶段 p99−p90 |
| --- | --- | --- | --- | --- | --- | --- |
| 线性 | 2.2 | 14.8 | 42.7 | 0.3 | 5.4 | 27.9 |
| `^(1/3)` | 28.1 | 52.9 | 75.3 | 14.1 | 37.9 | 22.5 |
| `asinh` s=0.05 | 24.7 | 61.4 | 82.8 | **4.0** | 41.4 | 21.4 |
| 语料 CDF（16 段） | 50.0 | 89.4 | 95.5 | 24.0 | 69.8 | **6.1** |

`asinh` 被排除：它在零附近的线性段是**压缩**极低值，低丰度基因只剩 4.0%，
比立方根还差，且没换来更多顶段对比。纯语料 CDF（完全直方图均衡）也被排除：
虽把密度范围用满，但顶段只剩 6.1 个百分点，值从 0.44 到 1.50（2.9 倍）几乎
压成同一密度——而"这个基因在这里格外高"正是最有价值的信号。

**（三）决定性指标是单基因内部的可读对比**，不是跨语料的分位差。用户读的是
一个基因的空间格局，而典型基因的全部动态范围都落在断点以下。按"该基因
中位区 → 最高区 的密度跨度（百分点）"实测：

| 变换 | 低丰度基因 | 中位基因 | 高丰度基因 | 全体中位 |
| --- | --- | --- | --- | --- |
| `^(1/3)` | 12.4 | 8.7 | 13.4 | 8.6 |
| 分段 D_LOW=0.70，高段**线性** | 19.6 | 13.4 | **5.9** | 10.3 |
| 分段 D_LOW=0.70，高段 `^0.5` | **19.6** | **13.4** | 13.0 | **11.0** |

低丰度 +58%、中位 +54%、全体中位 +28%，而高丰度基因只掉 0.4 个百分点。
**高段必须次线性而非线性**——线性会把高丰度基因压到 5.9。先前那个"顶段从 22.5
掉到 17.2"的损失，落到单基因可读性上几乎不存在。受损面也测清楚了：值 > 断点的
只占 10.0% 的（基因×区）对、分布在 22.9% 的基因里，而这些基因的内部对比被保住。

**（四）四组 `规则 × 指标` 各自标定。** 实测两个规则的 `mean` 参照差 21%，
共用一个会在切换规则时错标量程。分段在四组的"全体中位"上都胜出，
但**不是处处帕累托**，回退一并记录：

| 组合 | `^(1/3)` → 分段（低丰度 / 中位 / 高丰度 / **全体中位**） |
| --- | --- |
| `cell_weighted` / mean | 12.4→19.6 · 8.7→13.4 · 13.4→**11.0↓** · **8.6→10.8** |
| `cell_weighted` / detection | 12.9→**10.1↓** · 22.4→21.5↓ · 18.6→30.5 · **16.3→17.9** |
| `donor_balanced` / mean | 18.8→24.4 · 8.2→12.8 · 5.9→**4.4↓** · **12.3→18.0** |
| `donor_balanced` / detection | 36.4→**28.4↓** · 14.0→17.9 · 7.6→12.2 · **16.0→20.2** |

最大单项回退是 `donor_balanced/detection` 的低丰度基因 36.4→28.4，从"很好"退到
"好"，28 个百分点仍充裕。**已知局限**：`donor_balanced/mean` 的高丰度基因内部
对比在任何标定下都只有 4–6 个百分点，这是该聚合规则自身把高值压平的结果，不追。

**（五）高段幂次取 0.6，为的是压住断点上方的密度鼓包。** 任何 `P_HI < 1` 在断点上方
的导数都是无穷的，会让紧贴断点的值拿到不成比例的密度。以"高段超出按低段末段
斜率延伸的最大差"度量该鼓包（`cell_weighted/mean`）：

| `P_HI` | 高丰度对比 | 鼓包（百分点） |
| --- | --- | --- |
| 0.5 | 13.0 | 2.4 |
| **0.6** | **11.0** | **1.0** |
| 0.7 | 9.3 | 0.3 |
| 1.0（线性） | 5.9 | 0.0 |

0.6 把鼓包砍掉 58%，只让出 2.4 点高丰度对比；且它在 `donor_balanced/detection` 上
反而比 0.5 更好（11.8 → 12.2）。四组的"全体中位"从 0.5 降到 0.6 只掉 0–0.8 点。

**已知结构性特征（不是缺陷，不要"修"）**：`detection` 的鼓包恒为 13.6，不随 `P_HI`
变化。因为它的低段末段斜率 0.420 本就低于高段线性斜率 0.770（高段 0.61→1.0 的
窄带分到 30% 密度），所以 `detection` 的密度在断点上方天然加速——这与 √ 的
尖点无关，是"高检出率被强调"的固有后果，可接受。

**断点处斜率必然折转，不要试图 C¹ 衔接。** 实测 `cell_weighted/mean` 的低段末段
斜率是 0.320，高段若用线性则为 0.100——3.2 倍差距。既然刻意把 70% 的密度分给
底部 90% 的值，就不可能同时保持斜率连续（要 C¹ 需 `D_LOW ≈ 0.04`，荒谬）。
**值**连续是精确的（两支在断点均给 `D_LOW`），这才是该断言的不变量。

**为什么参照是固定的语料级常量而非选中集合的 max。** 后者会让"加入一个高丰度
基因"把已在屏上的基因一起压暗，容易被误读为"它们下降了"。固定标定使同一个值
在任何截图里都对应同一密度。

取 **p99.99 而非 max** 作 `reference`：max 会把 24% 的量程让给约 191 个离群值。
`detection` 的 `reference` 用**天然上界 1.0**而不用数据派生的 0.9877/0.9458：
它是比率，语义上界本就是 1；用派生值会让同一个 0.95 在两个规则下渲染不同。

**这个 351 倍完全是基因之间的，不是基因内部的。** 实测每个基因在 106 区内的
「中位值 / 最大值」：p25 = 0.159、中位 = **0.409**、p75 = 0.589——基因内部分布良性。
所以非线性标定服务的是跨基因可比，低段展开顺带改善了基因内部的可读对比。

### 4.3 偏移与抖动

- 基因 i 的偏移方向角 `2πi/n`，半径约 2px，**随透视缩放**（`point.perspective`），
  使偏移是同一个物理量而非同一个屏幕量
- 每点再叠 ≤1px 的**确定性抖动**（点索引哈希），打散体素网格造成的条纹

### 4.4 低值下限

值 > 0 时至少亮 3 点，使"有数据但很低"与"完全无数据"可区分。

## 五、标签级聚合

### 5.1 为什么不是区域级

29 个标签被多个区同时声明，被声明次数分布 `{1:61, 2:18, 3:8, 4:1, 5:1, 10:1}`。
最极端的一个：

```
label 114  HiH = head of hippocampus  ← 被 10 个 DigitalBrain 区声明
  CA1 CA2 CA3 | CA1R CA2R | CA1R CA2R CA3R | CA1U | CA1U CA2U CA3U
  CA2U CA3U | CA3R | DGR CA4Rpy | DGU CA4Upy | Sub
```

Allen 3D 对海马只有一个标签，DigitalBrain 在它里面有 10 个实体，**几何无法分开**。
现在这一点被藏住了：每个区各自算一个合成锚点（`stableAnchorFromPoints`，
种子含区域 id），于是海马这一坨里冒出 10 个不同位置的圆点——那个分离是编出来的。
点亮成片点云后只剩两条坏路：

- **等分体素**：实测中位点数 210 → 90，24 个区跌破 50 点，海马亚区只剩 **19 点**，密度分辨率毁掉
- **叠画**：10 层同色叠加，显示 max 而非各区真值，静默误报

### 5.2 聚合函数：support 加权平均

```
label 值 = Σ(value_r × support_r) / Σ(support_r)     r ∈ 声明该标签的区
```

等价于把各区的细胞汇总后再算：对检出率是精确的汇总检出率，对平均表达是精确的
加权均值。**正确性已用数据核实，不是想当然：**

- 152 个区域键的细胞数求和 = 12,057,607 = 数据集总数 16,352,123 的 **0.737 倍（< 1）**，
  证明这些标注桶**互不相交**，加权平均不重复计数
- 本体上领土确实重叠（层级树上 `CA1 CA2 CA3` 包含另外 6 个声明区），但
  **细胞集合不重叠**——一个细胞只有一个区域标注。领土重叠与细胞重叠是两件事
- 那个粗粒度的 `CA1 CA2 CA3` 只有 **59 个细胞、1 个供体**，值 0.3745 比邻居
  （CA1U 0.0199）高 18 倍——是小样本噪声。support 加权下它只占 **0.025%** 权重，自动被压没
- 10 个声明区细胞数合计 235,408，**多于**其共同祖先 `HIP` 的独立测量 176,145，
  所以聚合优于"改用 LCA 的值"

不采用"改用层级树 LCA 的值"：29 个多声明标签里只有 12 个的 LCA 在数据里有值，
且有反例——`Cun`（楔叶）的 LCA 是 `Ocx`（整个枕叶皮层，559,532 细胞），
特异性反而倒退。

### 5.3 代价

无法再从 3D 视图区分 10 个海马亚区的表达差异。这些差异改由点击后的详情面板
逐条列出（文字表格不受几何分辨率限制）。

## 六、置信度通道

### 6.1 三档来自层级树，且零新增数据

现有 `regionMappings[acronym].status` 与树关系**一一对应、零例外**（已核对）：

| 树关系 | status | 数量 | 点大小 |
| --- | --- | --- | --- |
| 同节点 | `recoverable_exact_or_union` | 45 | **1.9px** |
| Allen 是后代（精确并集） | `recoverable_exact_or_union` | 4 | **1.9px** |
| Allen 是祖先（父结构顶替） | `coarse_ontology_proxy` | 13 | **1.6px** |
| 跨分支（树无法衡量） | `curated_gyral_proxy` | 43 | **1.4px** |
| 无标签 | `outside_atlas_volume` | 1（SpC） | 不画 |

所以 `status` 字段**本身就是**树推导出的度量，浏览器端不需要新数据、不需要新脚本。

比原先的虚实线好在**有序**（1.9 > 1.6 > 1.4 对应可靠性递减，虚实线只有两档且无序）。
"跨分支"这个最差情形有明确解剖学解释：`FGM`（细胞构筑）与 `FSS`（表面脑回）是
两套分类法，Allen 141 个标签自己就 52/52 横跨两边，那 43 条代理是"某区在一套体系里、
几何只在另一套里"的必然产物。

### 6.2 混合置信度

只有 1 个标签的声明区置信度不一致（`label 51 HTHma`：两个精确 + 一个粗略代理）。
规则：**取最保守的一档**。代价是这一个标签画得略小。

## 七、命中网格

现在命中靠 `state.regionProjection` 里每区一个圆盘（`radius: Math.max(8, radius + 4)`），
`findRegionAt()` 按 z 从近到远找第一个满足 `hypot ≤ radius` 的。点云铺开后这个
8–12px 的圆盘会造成"点亮一大片却只有中心一小块能点"——大区投影可跨 100px 以上。

改为**绘制时顺手建屏幕网格**：16px 粒度（1200×800 → 75×50 = 3,750 格），每格存
z 最近的那个点的**标签 id + 基因序号**。mousemove 查一格，O(1)。

额外成本是每点一次数组写入（约 3 万次，相对已有的 3 万次 `fillRect` 可忽略），
换来两个能力：整片点云可点击，以及能知道点的是哪个基因——这让"点击查看该基因
在此处的明细"成为可能。

## 八、性能（实测）

充分预热（12 次）后每档 5 次取最小值，含投影数学而非只测 `fillRect`：

| 点数 | 耗时 |
| --- | --- |
| 22.4k | 1.8 ms |
| 45k | 3.7 ms |
| 90k | 12.2 ms |
| 180k | 28.7 ms |

帧预算 30 ms（`render()` 的 `now - lastFrame < 30` 节流）。标签级聚合下总点数
`14,252 × √n`：

| 基因数 | 总点数 | 估算耗时 |
| --- | --- | --- |
| 1 | 14.3k | ~1.2 ms |
| 4 | 28.5k | ~2.3 ms |
| 9 | 42.8k | ~3.5 ms |
| 20 | 63.7k | ~5.2 ms |

所以决策 1（不设基因数上限）是有实测支撑的，不是乐观假设。

## 九、接缝签名

```js
atlas.applyGeneValues({
  metric: "mean" | "detection",
  rule: "cell_weighted" | "donor_balanced",
  scale: { breakpoint, reference, lowKnots },  // index.densityScale[rule][metric]
  genes: [
    { symbol, colour, values: { acronym: number }, support: { acronym: cells } },
    ...
  ],
});
```

四个决定各有其理由：

- **数组而非映射**——顺序决定偏移方向角 `2πi/n`，映射没有稳定顺序
- **`colour` 由宿主提供**——`gene-atlas-view.js` 已拥有 `CHIP_COLOURS` 与
  `colourFor(symbol)`，芯片颜色与点云颜色必须一致；颜色只能有一个来源
- **`support` 随每个基因走**——标签级 support 加权聚合需要它，而 `label → regions`
  的逆映射只有 atlas 有（它自己的 `regionMappings`），所以**聚合放在 atlas 侧**，
  宿主不该复制一份几何知识
- **`scale` 与 `rule` 显式传入**——标定按 `规则 × 指标` 不同（§4.2），atlas 读不到
  `index.json`；传整个 `scale` 对象而不是拆成三个参数，因为三者必须同源同版

旧签名不保留：仓库里只有 `gene-atlas-view.js` 一个调用方，保留兼容分支等于永久
维护第二条代码路径。

## 十一、必须先修的两个既有缺陷

这两条不修，本设计无法正确落地或无法验证。

### 11.1 基因层现在没有可见图例

`drawRegions()` 确实把范围写进 `legendRange`（jsdom 实测 `"0.40–2.68"` / `"0–100%"`），
但那个元素在 `legendSingle` 内部，而 `syncCellTypeControls()` 在非 cells 层把
`legendSingle` 与 `legendAll` **都隐藏**：

```
基因层实测: legendSingle.hidden = true, legendAll.hidden = true, legendRange = "0.40–2.68"
```

范围算对了、写进去了、看不见。基因层眼下只剩 `mappingKey` 与解剖图例。

新增 `legendGenes` 块，在基因层显示：

- **每基因一行**：色块 + symbol + 该基因实测 min–max + **丰度位标**
  （在共用的 0–reference 轴上标出该基因 max 的位置，一眼看出整体是高丰度还是低丰度）
- 一条**密度标尺**：一小条从疏到密的点带，下方标出若干圆整值（如 0.05 / 0.1 /
  0.5 / 1 / 2）按 `norm()` 落到的位置，并在断点处加一道细分隔线。分段标定
  无法用一行公式讲清，所以**必须给刻度**——这是所有非线性色标/尺度的通行做法
- 把 `mappingKey` 的两档虚实线改成三档点大小示意（1.9 / 1.6 / 1.4px）

丰度位标是决策 7 的第二半：跨基因比较**格局靠密度、量级靠位标与数字**，
两者不争同一个通道。

### 11.2 测试脚手架只能渲染一帧

`test_gene_atlas_layer.js` 的 `drawOneFrame` 永远传 `callback(0)`，而 `render()`
有 30ms 节流（`lastFrame = performance.now()` 初值为正，首帧 `0 - lastFrame < 0`
过闸，之后 `0 - 0 = 0 < 30` 全部短路重排）。**所以 boot 之后每次 `drawOneFrame`
都是空操作**，既有 21 条测试里凡"改状态 → 渲染 → 断言"的，断言的都是 boot 那帧的
陈旧像素。

诊断本设计时我就是踩着这个坑先得出了两个错误结论（"drawRegions 在基因层没被调用"、
"基因层不写 legendRange"），改用单调递增时钟后两条都被推翻。

修法：驱动器改传单调递增时间戳（已在探针里验证有效）。不先修，新点云的渲染测试
会全部静默空转。

## 十二、测试策略

### 纯函数层（不进 jsdom）

- `P/√n` 分配律与窗口环形回绕
- 固定置换：值变化时已亮点不重排（同一标签两次不同值，亮点集合是包含关系）
- support 加权聚合等于细胞汇总后再算
- 分段标定的四个不变量：`v = 0` → 0；`v = breakpoint` → 恰好 `D_LOW`；
  `v = reference` → 1；`v > reference` → 封顶 1
- **断点连续性要直接比两支公式在 `breakpoint` 处的取值（应精确相等），
  不要用有限差分加小容差**。高段在断点上方导数无穷，`norm(bp + 1e-9)` 与
  `norm(bp)` 相差约 5.5e-6——拿 1e-6 当容差会误报。设计阶段我就这么误报过一次。
  同理，**不要断言斜率连续**（§4.2 第五段：折转是设计的一部分）
- 分段标定的**单调性**：对 10^4 个递增值断言 `norm` 不下降（节点表若有重复值
  会造成除零，守它）
- 抖动的确定性（同一点索引两次调用相同）

### 数据契约层

- `densityScale` 存在且 `规则 × 指标` 四组齐全；`detection` 的 `reference` 恒为 1；
  每组 `lowKnots` 恰好 13 项、递增、首项 0、末项等于 `breakpoint`
- 把 10 个海马声明区的加权聚合值与 `HIP` 的独立测量（176,145 细胞）交叉校验
- 59 细胞的 `CA1 CA2 CA3` 在聚合结果里的权重 < 0.1%

### 渲染层（jsdom + 修好的时钟）

- 总点数随基因数按 `√n` 增长
- 密度标定真的接到了渲染上：把某标签的值设为 `breakpoint`，其点亮数应约为
  窗口的 `D_LOW`（±1 点舍入误差）；设为 `reference` 则点亮整个窗口
- 命中网格对给定屏幕坐标返回正确的标签与基因序号
- 图例行数等于基因数，每行带该基因自己的 min–max 与丰度位标
- 密度标尺的刻度位置等于 `norm(该刻度值)`，且断点分隔线落在 `D_LOW` 处
- 三档点大小与 `status` 对应；`outside_atlas_volume` 的区不画点

## 十三、明确不在本次范围内

- **小倍数形式**（每基因一个小脑图、共用量程）。它其实是比较多个空间格局的最强
  实践（Allen 的 ISH 浏览器即如此），且完全绕开偏移/遮盖机制。不选是因为已定
  "单脑图叠加多基因"且现有架构是单 canvas。若日后重议形式，它应当第一个上桌。
- **绝对/相对量程切换**。决策 7 选了绝对量程；per-gene 归一化作为可选开关是
  合理的后续增强，但不在本次。
- 两处死代码的清理：`drawShell()`、`drawRegionContours()`、以及 `groupAnchors`
  （全文只有定义处，且缺 `Hypothalamus` 一项）。
- `github-pages/` 发布副本目前已与源码不同步（`gene-atlas-view.js` 的守卫写法不同），
  需在实施时由 `build_pages_release.py` 重新生成。
